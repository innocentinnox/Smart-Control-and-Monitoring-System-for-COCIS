\paragraph{RFID substitution.} Wokwi has no MFRC522 RFID reader part, so each card is a push button
with a fixed 32-bit UID, and the slide switch chooses which reader (entry or exit) was used. All of
this is hidden behind \file{components/nodes/include/rfid.h}: the rest of the system only ever sees
``card \emph{UID} scanned at side \emph{IN/OUT}''. A real reader replaces only \file{rfid.c}. Any
UID, including unregistered ones, can also be scanned with the CLI command \code{tap <UID> in|out}.

\paragraph{Peripheral sharing.} The LCD and RTC share one I2C bus (different addresses). The ESP32
LED controller (LEDC) provides all PWM: timer~0 at 50\,Hz for both servos, timer~1 at 5\,kHz for
the two lamps, and timer~2 for the buzzer, whose frequency changes per tone. The two light sensors
share ADC unit~1, protected by a mutex (\cref{sec:sync}).

\subsection{Wiring}
The Wokwi diagram is \textbf{generated}, not drawn by hand. \file{firmware/tools/gen_diagram.py}
reads the GPIO numbers from \file{board_pins.h}, places each part beside the header pins it uses,
routes every wire with explicit horizontal and vertical segments, adds a text label to every group,
and then checks the result: no two different nets overlap, no wire runs through a part, signal
wires never cross each other, and only power and ground cross signals, at right angles.
\code{make diagram} regenerates both \file{diagram.json} and \cref{fig:wiring}.
